## 1. 会话生命周期概览

```
用户发送消息
    │
    ▼
┌─────────────┐     无 session     ┌──────────────────┐
│ 查找 session │ ──────────────▶  │ 新建 session      │
│ (sessionMap) │                  │ --append-system-  │
└──────┬───────┘                  │ prompt 注入角色    │
       │ 有 session                └──────────────────┘
       ▼
┌─────────────┐     漂移/失效      ┌──────────────────┐
│ 漂移检测     │ ──────────────▶  │ 清除并重建 session │
│ (hash 比对)  │                  │ (递归, 最多 2 次)  │
└──────┬───────┘                  └──────────────────┘
       │ 无漂移
       ▼
┌─────────────┐
│ --resume     │
│ 恢复 session │
└──────┬───────┘
       │
       ▼
┌─────────────┐     超过 1M token  ┌──────────────────┐
│ 返回结果     │ ──────────────▶  │ 异步 /compact     │
│ 保存 session │                  │ 更新 session_id   │
└─────────────┘                  └──────────────────┘
```

**核心原则：**
- 每个 `conversationId + workDir + profile + channel + senderId` 组合对应一个独立的 Claude CLI session
- 群聊中每个用户拥有独立的 session（通过 `senderId` 隔离）
- session 持久化到工作目录的 `.claudetalk-sessions.json`，进程重启不丢失
- systemPrompt 变更后自动检测漂移并重建 session

## 2. Session Key 生成规则

**源码位置：** `src/core/claude.ts:117-129`

```typescript
export function getSessionKey(
  conversationId: string,
  workDir: string,
  profile?: string,
  channel?: ChannelType,
  senderId?: string
): string {
  const parts = [conversationId, workDir]
  if (profile) parts.push(profile)
  if (channel) parts.push(channel)
  if (senderId) parts.push(senderId)
  return parts.join('\x00')
}
```

**格式：**
```
conversationId\x00workDir\x00profile\x00channel[\x00senderId]
```

| 字段 | 说明 | 示例 |
|------|------|------|
| `conversationId` | 钉钉会话 ID（群聊或私聊） | `cidItK+4Ax4KQ2RRaNNJiImww==` |
| `workDir` | 项目工作目录绝对路径 | `/Users/suyin/Documents/WorkSpace/contact` |
| `profile` | 角色配置名称 | `help` |
| `channel` | 渠道类型 | `dingtalk` |
| `senderId` | 发送者 ID（仅群聊，实现每用户独立 session） | `01236123374864` |

**设计要点：**
- 使用 NUL 字符（`\x00`）作为分隔符，避免路径或 ID 中含有 `|` 等字符导致解析错误
- 不同 profile、不同 channel 的 session 完全隔离
- 群聊中传入 `senderId`，同一群内不同用户的会话互不干扰

## 4. 会话持久化与缓存

**源码位置：** `src/core/claude.ts:20-108`

### 存储位置

```
{workDir}/.claudetalk-sessions.json
```

### 文件格式

JSON 对象，key 为 session key（含 NUL 分隔符），value 为 `SessionEntry`：

```json
{
  "cidItK+4Ax4KQ2RRaNNJiImww==\u0000/Users/.../contact\u0000help\u0000dingtalk\u000001236123374864": {
    "sessionId": "04111a3c-6652-4c9c-b3a6-bc9258a62db8",
    "lastActiveAt": 1784357760294,
    "isGroup": true,
    "conversationId": "cidItK+4Ax4KQ2RRaNNJiImww==",
    "userId": "01236123374864",
    "channel": "dingtalk",
    "systemPromptHash": "20c0b976"
  }
}
```

### 内存缓存

```typescript
const sessionMapCache = new Map<string, Map<string, SessionEntry>>()

function getSessionMap(workDir: string): Map<string, SessionEntry> {
  if (!sessionMapCache.has(workDir)) {
    sessionMapCache.set(workDir, loadSessionMap(workDir))
  }
  return sessionMapCache.get(workDir)!
}
```

- 按 `workDir` 缓存，避免每次操作都读文件
- 首次访问时从文件加载，后续直接使用内存中的 Map
- 写操作（`saveSessionMap`）同时更新缓存和磁盘文件

### 加载逻辑（`loadSessionMap`）

1. 检查文件是否存在，不存在则返回空 Map
2. 读取 JSON，逐条解析为 `SessionEntry`
3. 旧版本数据含 `subagentEnabled` 字段时，标记为 `_legacySubagentSession`，后续触发一次性迁移清除
4. 解析失败的条目跳过，不影响其他条目

### 保存逻辑（`saveSessionMap`）

1. 遍历 Map，构建 JSON 对象
2. 清理内部字段（`_legacySubagentSession` 不写入磁盘）
3. 可选字段（`needsCompact`、`systemPromptHash`）仅在有值时写入
4. `JSON.stringify(entries, null, 2)` 格式化写入

## 6. Session 漂移检测

**源码位置：** `src/core/claude.ts:224-231, 448-465`

### Hash 算法

使用 djb2 哈希算法（避免引入 `crypto` 依赖）：

```typescript
function hashSystemPrompt(text: string): string {
  let hash = 5381
  for (let i = 0; i < text.length; i++) {
    hash = ((hash << 5) + hash + text.charCodeAt(i)) | 0  // hash * 33 + c
  }
  return (hash >>> 0).toString(16)
}
```

### 检测逻辑

在恢复 session 前，进行两道检查：

```typescript
if (existingSessionId && existingEntry) {
  // 检查 1：旧版 subagent 模式残留
  const isLegacySubagent = existingEntry._legacySubagentSession === true

  // 检查 2：systemPrompt 已变更
  const promptDrifted =
    existingEntry.systemPromptHash !== undefined &&
    currentSystemPromptHash !== undefined &&
    existingEntry.systemPromptHash !== currentSystemPromptHash

  if (isLegacySubagent || promptDrifted) {
    // 清除旧 session，递归重建（最多 MAX_SESSION_RETRY_COUNT = 2 次）
    sessionMap.delete(sessionKey)
    saveSessionMap(workDir, sessionMap)
    return callClaudeImpl(options, retryCount + 1)
  }
  args.push('--resume', existingSessionId)
}
```

### 触发场景

| 场景 | 原因 | 行为 |
|------|------|------|
| systemPrompt 修改 | `.claudetalk.json` 中角色提示词变更 | 自动清除旧 session 并新建 |
| 版本升级残留 | 旧版含 `subagentEnabled` 字段的 session | 标记后一次性清除 |
| Session 失效 | Claude CLI 返回 "No conversation found" 等错误 | 清除并重试 |

### 失败处理

重试次数超过 `MAX_SESSION_RETRY_COUNT`（2 次）时抛出异常：

```
[session] 升级/配置变更后重建 session 失败，已超过最大重试 (2)
```

## 7. 自动压缩（Auto-Compact）

**源码位置：** `src/core/claude.ts:295-382, 556-596`

### 触发条件

```typescript
const AUTO_COMPACT_TOKEN_THRESHOLD = 1_000_000  // 100 万 token
```

每次 Claude CLI 返回结果后，计算"这一轮模型实际处理的总 token"：

```typescript
const effectiveContextTokens =
  inputTokens + cacheReadTokens + cacheCreationTokens
```

当 `effectiveContextTokens > 1,000,000` 时，异步触发 `/compact`。

### 为什么用 effective_total 而非 input_tokens

> 旧实现只看 `usage.input_tokens`，但 Claude Code 中 `usage.input_tokens` 仅统计"非缓存"的新增 input；长跑 agent 几乎所有上下文都走 cache_read，`input_tokens` 永远是个位数——导致 200K 阈值永远不达标、压缩从未触发，session 滚到 1M+ 才被模型 400 拒绝。

改为按"这一轮模型实际处理的 token 总量"判断，阈值上调到 1M（模型 200K 窗口的 5 倍），兼顾"真的该压缩了"与"不要每次都压缩"。

### 压缩流程

1. **先返回结果给用户**（用户无感知压缩过程）
2. **异步执行压缩：**
   ```typescript
   const compactArgs = ['-p', '--output-format', 'json',
     ...engineConfig.skipPermissionsFlag, '--resume', response.session_id]
   ```
3. **向 stdin 发送 `/compact` 命令**
4. **压缩完成后更新 session_id：**
   ```typescript
   existingEntry.sessionId = response.session_id  // 新的 session_id
   existingEntry.needsCompact = false
   saveSessionMap(workDir, sessionMap)
   ```
5. **压缩期间的并发控制：** 新消息到达时若检测到 `compactingPromises` 中有正在进行的压缩，会等待压缩完成后再处理

### 并发保护

```typescript
const compactingPromises = new Map<string, Promise<void>>()
```

- 按 `sessionKey` 存储正在进行的压缩 Promise
- 新消息到达时，若该 session 正在压缩，等待压缩完成后再处理
- 压缩完成后从 Map 中移除

## 8. 群聊会话归属

**源码位置：** `src/channels/dingtalk/index_dingtalk.ts:873-1019`

### sessionOwnerId 决定逻辑

```typescript
let sessionOwnerId = callback.senderId  // 默认：发送者自己

if (isGroup && callback.text?.isReplyMsg && callback.text?.repliedMsg) {
  const replied = callback.text.repliedMsg
  const botUserIds = this.getAllBotUserIds()

  if (botUserIds.includes(replied.senderId)) {
    // 情况 A：回复机器人的消息 → 从历史中查找原始 session 所有者
    const found = this.findSessionOwnerFromHistory(
      callback.conversationId, replied.createdAt
    )
    if (found) sessionOwnerId = found
  } else {
    // 情况 B：回复其他用户的消息 → 加入该用户的 session
    sessionOwnerId = replied.senderId
  }
}
```

| 场景 | sessionOwnerId | 说明 |
|------|----------------|------|
| 直接发送消息 | `senderId` | 发送者自己的 session |
| 回复机器人的消息 | 从历史查找 | 找到机器人那条消息对应的原始提问者，复用其 session |
| 回复其他用户的消息 | `replied.senderId` | 加入被回复者的 session，实现对话延续 |

### sessionOwnerId 的作用

1. **Session 隔离：** 群聊中每个 `sessionOwnerId` 拥有独立的 Claude session
2. **历史消息过滤：** 只注入属于该 `sessionOwnerId` 的历史消息
3. **消息回复路由：** 机器人回复时 @ 正确的用户

```typescript
const allHistory = loadChatHistory(this.claudetalkDir, conversationId)
```

1. 按 `sessionOwnerId` 过滤——只看属于当前会话所有者的消息
2. 排除最后一条（即当前正在处理的消息）
3. 取最近 6 条

## 11. 内置指令

### 指令列表

| 指令 | 别名 | 说明 |
|------|------|------|
| `/new` | `新会话` | 清空当前会话记忆，下次发消息开启全新对话 |
| `/reset` | `清空记忆` | 同 `/new` |
| `/help` | `帮助` | 显示指令帮助信息 |

### 帮助文案

```
🤖 **ClaudeTalk 指令帮助**

- **新会话** 或 **/new** — 清空当前会话记忆，开启全新对话
- **清空记忆** 或 **/reset** — 同上
- **重启** 或 **/restart** — 重启 ClaudeTalk 机器人
- **帮助** 或 **/help** — 显示本帮助信息

发送其他任意消息将由 Claude Code 处理。
```

### /new 指令处理

```typescript
if (RESET_COMMANDS.has(command)) {
  const sessionSenderId = context.isGroup ? context.sessionOwnerId : undefined
  const hadSession = clearSession(
    context.conversationId, workDir, profile, channelType, sessionSenderId
  )
  const replyText = hadSession
    ? '🔄 已清空当前会话记忆，下次发消息将开启全新对话。'
    : '💡 当前没有活跃的会话记忆，发消息即可开始新对话。'
  await channel.sendMessage(context.conversationId, replyText,
    context.isGroup, sessionSenderId)
  return
}
```

**关键点：**
- 群聊中按 `sessionOwnerId` 清除对应用户的 session，不影响其他用户
- 私聊中 `senderId` 为 `undefined`，清除该会话的 session
- 返回是否曾存在 session，给出不同提示文案

### 指令匹配规则

```typescript
const strippedMessage = message.replace(/^@\S+\s*/, '').trim()
const command = strippedMessage.toLowerCase()
```

- 先去除 @ 前缀（群聊中被 @ 时）

## 12. 消息处理全流程

```
钉钉 WebSocket Stream 收到消息
    │
    ├─→ ACK 帧（立即返回，不阻塞）
    │
    ▼
异步处理：
    │
    ├─ 1. 更新 chat-members.json（发送者/机器人信息）
    │
    ├─ 2. 群聊/私聊策略检查（open/allowlist/disabled）
    │      └ 不通过 → 忽略（私聊 disabled 时回复提示）
    │
    ├─ 3. 解析消息内容（text / richText 等）
    │
    ├─ 4. 确定 sessionOwnerId（群聊 reply 路由）
    │
    ├─ 5. 写入群聊历史（chat-history）
    │
    ├─ 6. 添加 🤔 表情回应（表示正在思考）
    │
    ├─ 7. 构建上下文消息（群聊使用模板，私聊直接传原文）
    │
    ├─ 8. 调用统一消息处理器 (index.ts)
    │      ├─ 内置指令检查 (/new, /help, /restart)
    │      └─ 非指令 → callClaude()
    │           ├─ Session 查找 / 漂移检测
    │           ├─ 新建或 --resume
    │           ├─ spawn claude CLI
    │           ├─ 返回结果 + 保存 session
    │           └─ 异步 /compact（如超阈值）
    │
    └─ 9. 发送回复（Markdown / AI Card）
           ├─ 写入群聊历史
           └─ 解析 @ 提及 → peer-message 投递
```

## 13. 消息串行化与并发控制

**源码位置：** `src/core/claude.ts:293-410`

### 同一 Session 串行化

```typescript
const inFlightBySession = new Map<string, Promise<string>>()

export async function callClaude(options: CallClaudeOptions): Promise<string> {
  const sessionKey = getSessionKey(...)
  const previous = inFlightBySession.get(sessionKey)
  const work = (async () => {
    if (previous) {
      try { await previous } catch { /* 上一条的错误不影响当前 */ }
    }
    return callClaudeImpl(options, 0)
  })()
  inFlightBySession.set(sessionKey, work)
  // ...
  return work
}
```

**目的：** 防止同一 session 的两条消息同时 spawn `claude --resume`，导致 session 历史互相覆盖。

**行为：**
- 同一 sessionKey 的消息排队执行
- 前一条出错不影响后续消息处理
- 完成后从 Map 中清理

### 压缩期间消息等待

```typescript
const pendingCompact = compactingPromises.get(sessionKey)
if (pendingCompact) {
  await pendingCompact
}
```

如果 session 正在压缩，新消息会等待压缩完成后再处理，避免 `--resume` 到旧的 session_id。

## 15. 群聊/私聊策略

**源码位置：** `src/channels/dingtalk/index_dingtalk.ts:880-915`

### 配置项

在 `.claudetalk.json` 的 profile 中配置：

```json
{
  "groupPolicy": "open",       // open | allowlist | disabled
  "dmPolicy": "disabled",      // open | allowlist | disabled
  "groupAllowFrom": [],        // 群聊白名单（allowlist 模式）
  "allowFrom": []              // 私聊白名单
}
```

### 策略行为

| 策略值 | 群聊行为 | 私聊行为 |
|--------|----------|----------|
| `open` | 接收所有消息 | 接收所有消息 |
| `allowlist` | 仅接收白名单内发送者的消息 | 仅接收白名单内发送者的消息 |
| `disabled` | 忽略所有群聊消息 | 忽略并回复"暂不支持私聊"提示 |

### 通讯录答疑项目配置示例

```json
{
  "groupPolicy": "open",
  "dmPolicy": "disabled"
}
```

即：群聊开放接收所有消息，私聊关闭。
